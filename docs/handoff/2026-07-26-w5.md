## 3. Security properties, proven on a live server

Run against `brain ui` on 127.0.0.1:8765 (read-write) and :8766 (`--read-only`).

**CSP on a real response**
```
$ curl -sS -D - -o /dev/null http://127.0.0.1:8765/api/health
HTTP/1.1 200 OK
content-security-policy: default-src 'none'; script-src 'self'; style-src 'self';
  img-src 'self' data:; connect-src 'self'; base-uri 'none'; form-action 'none';
  frame-ancestors 'none'
x-content-type-options: nosniff
referrer-policy: no-referrer
cache-control: no-store
```
No nonce and no `'unsafe-inline'`, which is only sustainable because the shell
has zero inline `<script>` / `<style>`. `tests/test_ui_static_assets.py`
enforces that, and `test_ui_security.py` asserts the header is present on 200s,
404s **and 403 refusals**.

**DNS rebinding — Host validation** (an Origin check cannot stop this)
```
$ curl -sS -H "Host: evil.example" http://127.0.0.1:8765/api/health
Invalid host header        status=400
$ curl -sS http://127.0.0.1:8765/api/health
status=200
```

**Read-only refuses in middleware, before routing**
```
$ curl -X POST -H "Origin: http://127.0.0.1:8766" -H "Content-Type: application/json" \
       -d '{"title":"Should Not Exist"}' http://127.0.0.1:8766/api/notes
{"error":{"code":"read_only",...}}                      status=403

$ curl -X POST ... http://127.0.0.1:8766/api/no-such-endpoint
{"error":{"code":"read_only",...}}                      status=403   <-- not 404
```
The **403-not-404 on a nonexistent path is the proof it precedes the router**: a
per-handler decorator cannot refuse a route that has no handler.
`SELECT count(*) ... WHERE title='Should Not Exist'` → `0`.

Also verified: cross-origin mutation → 403 `origin_mismatch`; **missing** Origin
→ 403 (fail-closed); `Sec-Fetch-Site: cross-site` → 403; form content-type →
415; token gates `/api/*` but not the shell; every read route 405s on
POST/PUT/DELETE and every write route 405s on GET.

## 4. Spec corrections for Wave 6

1. **§4.3 is wrong about markdown-it.** It states `MarkdownIt("commonmark")`
   defaults to `html=False`. On markdown-it-py 4.2.0 that preset renders raw
   HTML **through** — `<script>alert(1)</script>` emits unescaped. `render.py`
   passes `{"html": False}` explicitly. Following the document would have
   produced an artifact whose XSS defence reads as present and is absent.
   markdown-it's `validateLink` *does* hold, verified: `javascript:`,
   `vbscript:`, `data:text/html` and `file:` all emit **no `<a>` at all**, and
   mixed case does not evade it.
2. **§2.1's nested `static/css/` + `static/js/` layout is superseded.** The
   declared package-data globs are flat (`static/*.css`, `static/*.js`), and
   `*` does not cross `/` — a nested asset would be missing from the wheel with
   a blank page and no error. Layout is flat; a glob-coverage test enforces it.
3. **§2.1's `assert_within_vault(target, vault_root, *, label)`** — the landed
   signature has no `label` parameter.
4. **§3.6's `editable`** — also emits `movable`, since move is vault-tier only.

## 5. Why no `pyproject.toml` change is needed

- **`py.typed`:** not required. The reported mypy error
  (`Skipping analyzing "brain.ui.app": ... missing py.typed marker`) was mypy's
  generic text for *unresolvable module* — `app.py` did not exist yet. `brain`
  has never shipped `py.typed` and no other module errors. Fixed by removing the
  lazy `create_app` re-export from `brain/ui/__init__.py`; callers use
  `from brain.ui.app import create_app`. `mypy src/` is clean on 204 files.
- **`starlette` / `uvicorn`:** spec §2.1 wanted them promoted to explicit
  `[project.dependencies]`. They resolve today via `mcp>=1.0` (starlette 1.3.1,
  uvicorn 0.49.0) so the UI **works**, but the dependency is undeclared. This is
  a real latent risk — if `mcp` ever drops them, `brain ui` breaks at import
  with no warning. Recommended (not required for this release):
  ```toml
  # in [project.dependencies]
  "starlette>=0.47,<2",
  "uvicorn>=0.30",
  ```
  Adds **zero** new wheels; only stops relying on a transitive.
- **`filterwarnings`:** handled with a module-scoped
  `pytestmark = pytest.mark.filterwarnings(...)` instead of a global entry.

## 6. Decisions taken

**Confidential note bodies (F6) — option B, bind-conditional. Ruled by the
coordinator; implemented with all three conditions.** Bodies render on a
loopback bind (CLI-equivalent trust, matching `brain show`); on a non-loopback
bind they are **withheld** unless the operator passes `--include-confidential`.

1. **Computed once at startup** into `UiContext.serve_confidential_bodies`
   (`server.build_context`), never re-derived per request. No
   `X-Forwarded-For` / proxy trust question enters this surface at all.
2. **Withholding is total.** The enumeration asks of every emitted field not
   *"is this the body?"* but **"is this derived from the body?"** — which is
   what catches summaries, snippets, excerpts and match-membership in one pass.
   Full sweep, all tested in `tests/test_ui_confidential.py`:

   | Emitted field | Derived from body? | Behaviour when withheld |
   |---|---|---|
   | `body` | yes (is it) | `None` |
   | `html` | yes | `""` |
   | `summary` | **yes — LLM-generated from it** | **omitted** |
   | `body_hash` | yes | omitted (also a weak oracle) |
   | search `snippet` | **yes — lifted from `chunks`** | `""` + `withheld: true` |
   | **search membership** | **yes — the oracle** | **row excluded entirely** |
   | **facet counts** | **yes — same match set** | computed with the same filter |
   | `PUT` | — | 403 `body_withheld` |
   | `title`, `vault_path`, `tier`, `draft`, `content_type`, tree | no — user-authored / structural | **visible on purpose** |
   | `tags` | *usually* no; see caveat | visible |

   **The match-membership oracle is the sharpest of these.** Redacting a
   snippet hides the passage but leaves the row, and a row that appears for
   query X reveals that the withheld body contains X — so the body is
   recoverable a word at a time by anyone who can reach the server. Closed by
   passing `sensitivity="normal"` to `hybrid_search` **and** to the facet
   predicate on a withholding bind. Snippet redaction is kept as a second
   layer, proven independently by
   `test_snippet_redaction_survives_as_defence_in_depth` so a passing first
   layer cannot hide a broken second one. Nothing is lost: the tree still
   lists every note by title, so "you can see it exists" holds where it
   belongs.

   Nothing logs document content (house rule, CLAUDE.md), and no error message
   embeds body text. The tests assert the secret phrase is absent from the
   **whole serialized response**, not just the fields anticipated.

   **KNOWING EXCEPTION — `tags` are body-derived and are shown anyway.**
   This is a decision, not a gap. `brain tag --auto`
   (`enrichment.propose_tags`) generates tags from the body with an LLM, so on
   an auto-tagged confidential document `tags` **fails the derived-from-body
   rule**. They are shown regardless, for three reasons:

   1. **The title is already visible by ruling, and is strictly higher
      entropy** — free text, frequently a near-summary of the note. If a
      visible title is acceptable, a handful of tags is acceptable *a
      fortiori*; withholding tags would close a channel narrower than one
      deliberately left open.
   2. **Tags draw from a shared corpus-wide vocabulary**, so a tag reveals
      category membership rather than content.
   3. **They are load-bearing** — the tag facet and navigation depend on them,
      so withholding degrades the product for every user.

   **Revisit if tag provenance is ever recorded.** Today an auto-generated tag
   and a user-authored one are indistinguishable at read time, so selective
   withholding is not available even in principle. If a marker is added,
   this decision should be reconsidered — withholding only the `--auto` tags
   would cost nothing.

   Reversing it entirely is a one-line change in `read_note`.
3. **Shape matches MCP `brain_show` exactly** — `withheld` (string) and
   `sensitivity` keys, emitted **only** on the withheld path. Only the
   *trigger* differs (bind vs. an explicit argument), which is intended.
   `test_normal_document_payload_is_byte_identical_across_modes` pins that a
   normal document's payload is identical in both modes, adopting w2b's
   byte-identical discipline.

The startup panel always prints the effective mode, so an operator who passes
`--include-confidential` on a non-loopback bind sees a red
`Confidential  bodies SERVED over the network` line.

**`VALID_SOURCE_KINDS` duplicated, not extracted.** `source_kinds.py` never
landed and `cli.py` is coordinator-only.
`tests/test_ui_schemas.py::test_source_kinds_match_the_cli_exactly` pins the two
sets equal and names both file paths on failure.

## 8. Flagged for someone else

**`vault/note_builder.create_vault_note` fails silently on a non-autocommit
connection** (F8 / w2b territory, pre-existing). It writes the file to disk
*before* the DB work and returns a document id, raising nothing — so on a
caller that has not set `conn.autocommit = True`, you get files on disk, ids
returned, and no rows. Observed: 5 notes created, 5 files written, **1 row**.
The autocommit contract is documented in `vault/delete.py`'s module docstring
but not enforced or checked. A one-line `if not conn.autocommit: raise` would
turn a silent divergence into a clear error.
