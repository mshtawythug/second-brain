**Measured before/after:**

| | before | after |
|---|---|---|
| `BRAIN_SECRET_GUARD=block brain list` | Rich traceback, exit **1** | boxed `Error:` panel, exit **2** |
| message | `ConfigError: BRAIN_SECRET_GUARD must be one of warn/redact/reject/off (got 'block')` | identical text, inside the panel |

Verified points that are easy to get wrong:

- **Sub-apps are covered.** `vault` / `note` / `graphrag` invocation nests
  inside the root group's `invoke()`, so one handler reaches all of them.
  Tested explicitly with a nested sub-app.
- **Only `ConfigError` is intercepted.** A handler that swallowed everything
  would turn real defects into tidy usage errors — worse than the traceback
  this ticket removes. Pinned by `test_a_genuine_bug_still_raises`.
- **Exit 2, not 1** — matching Typer's convention for "you invoked this
  wrong", and matching `brain list --sensitivity <typo>`, which is the
  inconsistency #24 is about.
- **It generalizes.** Tested on `BRAIN_AGENT_ID` as well as
  `BRAIN_SECRET_GUARD`; w5 confirmed the bug is general, and a per-variable
  fix would have left every other `BRAIN_*` still crashing.
- **`ConfigError` stays framework-free.** Making it inherit
  `click.ClickException` would also fix the presentation and would couple
  `config.py` to a CLI framework the MCP server and `brain ui` do not use.
  Asserted by `test_config_error_is_not_a_click_exception`.

One caveat for your verification: a **single**-command Typer app collapses to
a bare command and renders a different (wrong-looking) message. The real CLI
has ~50 commands so this never bites in production, but it will if you test
the handler in a one-command scratch app.

## A.2 Wave 4 + task #17 doc deltas for Wave 6

### `docs/cli-reference.md`

**`brain recall`** — retrieval sized for an agent's context window, as opposed
to `brain search`, which ranks pointers for a human.

```
brain recall <QUERY> [--budget N] [--max-candidates N] [--json] [--agent ID]
             [ …the same metadata filters as `brain search` ]
```
Emits a `# recall:` header plus `[N]`-cited passages, one per document, whose
total is guaranteed ≤ `--budget` (default `BRAIN_RECALL_BUDGET_TOKENS`, 2000).
When the budget cannot hold even the top passage, one **truncated** passage is
returned rather than nothing.

**`brain mark-confidential` / `brain mark-normal`** — raise or lower a
document's trust tier. Both are idempotent. `mark-normal` is the **only**
sanctioned downgrade path, because re-ingest is escalate-only.

**`brain list --sensitivity normal|confidential`** — filter by tier. An
unrecognized value is a usage error (exit 2), never a silent empty list.

**`--agent ID`** on `search`, `recall`, `rate`, `ingest-stdin`. Precedence is
flag > `BRAIN_AGENT_ID` > unattributed. `brain ingest` / `ingest-dir`
deliberately have **no** `--agent`: they are human paths, and attributing a
hand-run ingest to an agent would be a fabricated fact.

### `docs/configuration.md`

| Variable | Default | Meaning |
|---|---|---|
| `BRAIN_AGENT_ID` | unset | Default agent attribution for every surface. Must match `^[A-Za-z0-9][A-Za-z0-9._:-]{0,63}$`; a malformed value fails at `Config.load()`. |
| `BRAIN_RECALL_BUDGET_TOKENS` | 2000 | Default `brain recall` budget. |
| `BRAIN_RECALL_PASSAGE_TOKENS` | 120 | Context window stitched around each best chunk. |
| `BRAIN_RECALL_MAX_CANDIDATES` | 25 | Upper bound on candidates fetched before packing. |

### `brain usage` (F7)

```
brain usage [--days 30] [--json] [--raw-queries] [--limit 10]
```

Counts searches, opens, feedback events and ingests over the trailing window,
broken down by day, by surface (`cli`/`mcp`/`wiki`) and by agent. Also reports
search-latency p50/p95 from migration 024's `duration_ms`.

- **`--json` withholds raw query strings by default.** A query log records what
  someone was *looking for*, including searches that returned nothing — often
  more revealing than any document it found. Pass `--raw-queries` to include
  them. Counts are identical either way; only the label changes.
- **Human output is deliberately not redacted** — the terminal is inside the
  trust boundary, and a user asking "what do I search for most" needs the real
  strings to act on the answer.
- A document with no `agent_id` reports as **`(unattributed)`**, never folded
  into a surface. Every pre-027 row is genuinely unattributed and saying so is
  more useful than guessing.
- On a DB missing migration 019/023/024/027 the command **fails** with the
  `brain init` hint rather than reporting confident zeroes. That is the
  opposite of the telemetry *write* path, which swallows so the daily-driver
  search keeps working — a silently incomplete report is worse than none.

### Limitations to state plainly

- **`search_queries` does not distinguish a recall from a search** in this
  release. Both log with `source='mcp'|'cli'`; there is no `kind` column. A
  reader counting "searches" is counting recalls too.
- **`brain_recall` mints no `session_id`, deliberately.** The `no_click` gap
  detector flags any logged search with a session id that no later open
  follows. A recall's *result is the content*, so an agent essentially never
  calls `brain_show` afterwards — minting one would make every recall look
  like a search failure and poison `brain gaps`.
- **`include_confidential` is a speed bump, not authentication.** A
  cooperating LLM can pass `true`. What it prevents is a confidential body
  being pulled into context incidentally, and it makes deliberate retrieval
  visible in the call record.
- **`regenerate_vault_file` refuses vault-tier rows.** Any future "update a
  field and re-mirror" command hits this; the pattern to copy is
  `_set_sensitivity`'s tier branch (rewrite one frontmatter field in place for
  vault tier, regenerate for ingested tier).

## 2. Doc deltas for Wave 6

### `docs/cli-reference.md`

Add `brain note move` beside `brain note rename`:

```
brain note move <ID-PREFIX> <NEW-FOLDER> [--dry-run] [--yes] [--no-link-refactor] [--vault PATH]
```

| Flag | Default | Meaning |
|---|---|---|
| `--dry-run` | off | Print the plan; write nothing. Skips the prompt. |
| `--yes` / `-y` | off | Skip the confirmation prompt. |
| `--no-link-refactor` | off | Leave `[[…]]` references alone. The file still moves. |
| `--vault` | config | Override the configured vault path. |

Points worth stating in the reference text:

- `NEW-FOLDER` is vault-root-relative. `""` and `"."` mean the vault root; a leading slash is
  stripped (so `/projects/atlas` == `projects/atlas` — it never means the filesystem root);
  a missing folder is created.
- The document id is preserved, so incoming backlinks survive.
- **Safe to run with `brain vault sync --watch` and `brain-mcp` live** — no daemon needs to be
  stopped. The file is relocated with an atomic rename and `documents.vault_path` is repointed
  before the follow-up sync, so the watcher takes its non-destructive move branch.
- There is no `--force` and no overwrite path: a note already at the destination is a hard error.
- Moving a note into the folder it already occupies prints `already in <folder> — nothing to do`
  and exits 0.

Exit codes: `0` success or no-op · `1` collision / not vault-tier / missing file / declined
prompt / post-move sync error · `2` destination escapes the vault.
