## What ships

1. **`UiContext.serve_abs_path: bool = False`** (`src/brain/ui/context.py`). The one derived
   boolean the ticket names. `server.build_context` sets it to `loopback`, the value it already
   computes as `security.is_loopback(host, resolved)`, which is
   `ui.context.address_class(...) == "loopback"`: the same classification that D8's
   `ingest_enabled` (`loopback and not read_only`) and `serve_confidential_bodies` start from.
   A wildcard bind (`0.0.0.0`, `::`), a LAN address, a loopback alias (`127.0.0.1.nip.io`) and an
   unresolved hostname are all "not loopback", so none of them gets `abs_path`. The dataclass
   default is the fail-closed one, like `serve_confidential_titles` and `ingest_enabled`: a
   context built without it (every fixture that does not care) sends no absolute path.
2. **`abs_path` in `GET /api/notes/{id}`** (`src/brain/ui/notes_service.read_note`). The absolute,
   resolved path of the note's vault file. It is added only when all of these hold:
   - `ctx.serve_abs_path` is true;
   - the body is **not withheld**. The key is written after `read_note`'s withheld early return,
     so a confidential note whose body this server withholds (`serve_confidential_bodies` false)
     never carries `abs_path`. A real loopback build always serves confidential bodies, so this
     branch is reached only by a hand-built context. It fails closed anyway, because a later change
     to either flag must not turn the path into the one field that escapes the lens;
   - the note has a `vault_path` and the file exists. A missing mirror has no file an editor
     could open.
3. **"Copy path" button** (`src/brain/ui/static/js/inspector.js`), in `.note-bar`, so it sits in
   `head` and the inspector host keeps exactly two grid rows. It copies `note.abs_path` when the
   payload has one, otherwise `note.vault_path`. It is rendered only when `window.isSecureContext`
   and `navigator.clipboard` both hold, and the note has a path. An `http://127.0.0.1` page is a
   secure context. An `http://` LAN page is not, so the button is simply absent over `--lan`. The
   click calls `navigator.clipboard.writeText(path)`, then sets a `role="status"` span's
   `textContent` to "Copied", or to "Copy failed (<error name>)" when the promise rejects. No
   `innerHTML`, no `obsidian://` link (RM-23.D1), and no server-side editor spawning.

## Risks

- Browsers differ in their clipboard permission prompts. The button reports a rejection instead
  of failing silently.
- `inspector.js`'s ceiling estimate is about 540 (the ticket). The button is a small helper function.

## Deviations

- **`notes_service.py` grows by a few lines, against a §2.2 budget of 0.** The ticket's scope
  names "the `GET /api/notes/{id}` payload", and `read_note` is where that payload is built. The
  §2.2 row's reason ("Ingest lives in `ui/ingest_service.py`") is about ingest, which this is not.
  The file stays well under 800.
- **`abs_path` is also withheld when the body is withheld, and when the mirror file is missing.**
  The ticket names only the loopback gate. The lens is the team lead's privacy requirement. The
  file-exists condition stops the payload from offering a path an editor cannot open. In both
  cases the button falls back to `vault_path`.
- **`inspector.js` is 550 lines, not about 540.** The ticket's estimate; the extra ten are the
  helper's comment, which says why the button is absent over `--lan` and that a failure is
  reported. The file stays well under 800.
- **No skill is updated.** DoD item 13 asks for "the relevant skill"; no skill under `skills/`
  covers the `brain ui` note pane.
