# RM-32 — OCR, and image-only PDFs

> **For agentic workers:** REQUIRED SUB-SKILL: Use team-driven-development to implement this plan task-by-task.

Ticket: `#### RM-32` in `docs/specs/2026-10-23-roadmap-completion-design.md` (§2.2 ceiling budgets,
§2.3 settings leaves, §2.6 dependencies). Branch `feat/rm-32-ocr` off `second-brain/master`
(`934a182`).

## Problem

An image-only PDF (a scan, a photographed receipt) has no text layer. `extract_pdf` returns an
empty body, `ingest_document` stores nothing, and the CLI reports `skipped (empty document)`. The
document is not searchable.

## Scope

In: a new leaf `src/brain/ingest/ocr.py`; `src/brain/ingest/pdf.py`; a new settings leaf
`src/brain/settings/ocr.py`; `pyproject.toml` (two explicit base dependencies); a `brain doctor`
row in a new leaf `src/brain/doctor_ocr.py`, composed into `doctor_runtime.py`.

Out: images outside PDFs (RM-33), handwriting, a `[ocr]` extra (RM-32.D2: it would install
nothing `pdfplumber` does not already require).

No over-800 file is touched: `ingest/__init__.py`, `cli_ingest.py`, `cli.py` and `config.py`
are unchanged, so the CLAUDE.md ceiling table needs no row edit.

## Design

### `ingest/ocr.py` (new leaf)

- `OcrEngine` Protocol: `name: str` and `image_to_text(png: bytes, *, lang: str, timeout: float)
  -> str`. `name` is what `metadata.ocr.engine` records; the spec's Protocol lists only
  `image_to_text`, and `name` is the one addition, so `pdf.py` never hard-codes an engine name.
- `OcrError(BrainError)` with a content-free `log_detail` (`exit 1`), the `DirectoryRefreshError`
  pattern, so `describe_failure` prints `OcrError[exit 1]`. `OcrTimeoutError(OcrError)`. Both end
  in `Error`, so `EXCEPTION_CLASS_NAMES` is unchanged.
- `Runner = Callable[[list[str], bytes, float], subprocess.CompletedProcess[bytes]]`; the default
  `run_subprocess` is `subprocess.run(cmd, input=..., capture_output=True, timeout=...,
  check=False)`. A runner may raise `subprocess.TimeoutExpired` or `OSError`.
- `TesseractOcr(binary, runner)`: runs `[binary, "stdin", "stdout", "-l", lang]` with the PNG on
  stdin. Timeout → `OcrTimeoutError` (`from None`: `TimeoutExpired` carries partial output);
  `OSError` → `OcrError` from it (`describe_failure` keeps the errno); non-zero exit → `OcrError`
  with `log_detail="exit N"`. **stderr is never read into a message**, because tesseract can echo
  recognised text there.
- `PAGE_TIMEOUT_S = 60.0`, `RENDER_DPI = 200`.
- `OcrSetup(settings, engine)` and `resolve_ocr(env, *, which=shutil.which, runner=None)`:
  `engine` is `None` when `BRAIN_OCR=off` or when `tesseract` is not on `PATH`.
  `OcrSetup.missing_binary` is true only for the second case, which is when the hint is due.
- Doctor helpers: `tesseract_version(binary, runner)` (`tesseract --version`, first line) and
  `installed_languages(binary, runner)` (`tesseract --list-langs`).

### `settings/ocr.py` (new leaf, RM-08 pattern)

`OcrSettings(mode, lang, max_pages)`, `load_ocr_settings(env)`:

| Variable | Default | Rule |
|---|---|---|
| `BRAIN_OCR` | `auto` | `auto` (OCR when `tesseract` exists) or `off` |
| `BRAIN_OCR_LANG` | `eng` | tesseract language codes joined by `+` (`eng+deu`): `[A-Za-z0-9_]+` each, so it can never be read as an option |
| `BRAIN_OCR_MAX_PAGES` | `50` | integer in `[1, 1000]` |

A bad value is a `ConfigError` naming the variable, never quoting the value (`_env`'s rule).

### `pdf.py`

1. pypdf text, then the existing pdfplumber fallback when it is empty (its `pragma: no cover`
   comes off: image-only fixtures now reach it).
2. **Trigger:** the stripped text averages under `MIN_CHARS_PER_PAGE = 25` per page **and** at
   least one page within the cap carries an image object (`pypdfium2`,
   `FPDF_PAGEOBJ_IMAGE`). The image condition is an addition to the spec's wording, and it is what
   makes acceptance criterion 2 hold: the repo's own `tests/fixtures/sample.pdf` is born-digital
   with 19 and 21 characters per page, so the average rule alone would OCR it. A page with no
   image has nothing to recognise.
3. The OCR settings and engine are resolved only once the average rule fires, and **before**
   pdfium opens the file, so a PDF with a full text layer never reads `BRAIN_OCR*` or looks for
   `tesseract`, and with `BRAIN_OCR=off` pdfium never opens it (security review round below).
4. Pages `1..max_pages` are rendered at 200 dpi with `pypdfium2`, encoded as PNG with Pillow, and
   passed to the engine. A page whose render or OCR fails (timeout, non-zero exit,
   `PdfiumError`) is skipped with a class-only WARNING (`describe_failure`). Pages past the cap are
   not rendered; an INFO line gives the counts.
5. Pages with text are joined as `[page N]\n<text>` blocks, and `metadata.ocr = {"pages": n,
   "engine": "tesseract"}`, where `n` is the number of pages whose text is in the body. When no
   page yields text, the extracted text (possibly empty) is kept and `metadata.ocr` is absent.
6. **Hint:** trigger fired, `BRAIN_OCR=auto`, no `tesseract` on `PATH` → one WARNING naming the
   missing binary (`brew install tesseract`), and the document stays empty, so the CLI still says
   `skipped (empty document)`. The CLI does not configure logging, so the WARNING reaches stderr
   through `logging.lastResort`; `cli_ingest.py` (over the ceiling) is not touched.
   `BRAIN_OCR=off` logs nothing: it was chosen.

The secret guard needs no change: it runs on `doc.content` inside `ingest_document`, whatever
produced it. A test proves it on OCR text.

### Doctor row `ocr` (`doctor_ocr.py`, composed in `doctor_runtime.py`, +4 lines of its +60 budget)

- `ConfigError` → WARN with the message (names the variable only).
- `BRAIN_OCR=off` → OK `off, BRAIN_OCR=off`.
- No `tesseract` → OK, detail says image-only PDFs ingest empty and how to install it. Not a
  WARN: OCR is optional, and the same rule makes the reranker's `not configured` an OK.
- `tesseract --version` fails → WARN (class only).
- The language is not in `--list-langs` → WARN, remedy `brew install tesseract-lang`.
- Otherwise OK `tesseract <version>, lang <lang>, up to <n> pages`.

### Dependencies (§2.6)

`pypdfium2` and `Pillow` become explicit base dependencies, with evidence blocks. Measured in the
RM-32 venv on 2026-10-30 (uv, Python 3.11): `pdfplumber` 0.11.10 requires `pypdfium2>=5.9.0` and
`Pillow>=12.2.0`; the resolve has **pypdfium2 5.14.0** and **Pillow 13.0.0** (the spec's
2026-10-23 measure was 5.13.0 / 12.3.0, so both moved since). Declaring them adds zero wheels.
Floors are the versions the tests ran on: `pypdfium2>=5.14`, `Pillow>=13.0`. Unbounded above, like
the other extractor dependencies.

## Security review round (#99, at `bb6fb7a`)

- **HIGH, render size.** The MediaBox is the file's to set: a 200,000-pt page with a 1x1 image
  asked pdfium for ~309 Gpx, and neither pdfium nor `to_pil()` applies Pillow's bomb limit.
  `render_scale(w, h)` now gives `min(200/72, sqrt(MAX_PIXELS / (w*h)))` with `MAX_PIXELS =
  70_000_000` (A0 at 200 dpi is ~62 Mpx). Below `MIN_RENDER_DPI = 50` it raises
  `PageTooLargeError` (an `OcrError`), as it does for a non-positive or non-finite area, and the
  page is skipped with the class-only warning. `MemoryError` joins the caught tuple.
- **HIGH, thin-page bypass (sec-99b, at `c72bdb8`).** pdfium rounds each side UP, so a thin page
  escaped the area-in-points cap: 0.01 x 3.5e8 pt got scale 2.78, a 1 x 972,222,223 px bitmap
  (13.9x the cap), and 1e-30 x 1e30 pt overflowed the C int ctypes hands pdfium. The scale is now
  the largest `s` with `(w*s + 1) * (h*s + 1) <= MAX_PIXELS` (stable quadratic form), so
  `ceil(w*s) * ceil(h*s)` never exceeds the cap; `MAX_SIDE_PX = 32_767` (tesseract's limit) caps
  each side; width and height must each be positive and finite (-100 x -100 had passed); and the
  page loop also catches `ArithmeticError`, `ValueError` and `ctypes.ArgumentError`. A separate
  `ceil(w*s) * ceil(h*s) > MAX_PIXELS` check is not kept: the sizing makes it unreachable, and a
  grid test asserts that post-condition instead. Six mutants (side cap, ceil-aware fit, per-side
  positivity, and each newly caught class) were all killed.
- **Thin cases and a sub-pixel side (aud-99).** 3e7 x 0.01 pt (83 Mpx under the old cap) and
  1e8 x 0.001 pt are regression tests. A page whose shorter side renders under one pixel is
  refused: it holds no line of text.
- **MEDIUM, embedded-image decode (rev-99, at `c72bdb8`).** pdfium decodes each image XObject at
  its native size to draw a page, whatever the page size: a 30,000 px square flate image (an
  875 KB file) peaked at 1.11 GB. Before `render()`, `embedded_image_pixels` sums
  `PdfImage.get_px_size()` over `page.get_objects(filter=(FPDF_PAGEOBJ_IMAGE,))`, which reads
  only the dictionaries and recurses into Form XObjects. A page over `MAX_IMAGE_PIXELS` (280 Mpx,
  4x `MAX_PIXELS`) is skipped with `PageTooLargeError`; a size that cannot be read fails closed.
  The bound is a `render_page_png` parameter. The tests declare a 12,000 px square image (a
  140 KB file) written with `zlib.compressobj` and never decoded, direct and inside a Form
  XObject. Mutants killed: the bound, its call, the fail-closed path, the sub-pixel check.
- **MEDIUM, per-document time.** `OCR_DEADLINE_S = 600`, read through an injectable `clock`
  before each page; each page's timeout is `min(60 s, remaining)`. At the deadline OCR stops,
  keeps what it read, and logs a count-only WARNING.
- **LOW, OCR off.** The settings are resolved before pdfium opens the file, and `off` returns
  first, so the untrusted file never reaches a second parser. A PDF with a full text layer still
  never reads the knobs; a sparse one now does, so a bad knob fails its ingest loudly.
- **LOW, image probe.** `_has_image` reads only `islice(document, max_pages)`.

## Test isolation

`tests/ocr_isolation_plugin.py` (autouse, registered in `tests/conftest.py`'s `pytest_plugins`,
the `rerank_isolation_plugin` pattern) sets `BRAIN_OCR=off` and clears the other knobs for every
test, so no test shells out to a real `tesseract` through `extract_pdf(ocr=None)` or the doctor
row. `tests/test_ocr_isolation.py` proves it in a child pytest that exports OCR on. A test that
needs OCR passes an `OcrSetup` or sets the knob. `tests/conftest.py` gains the one plugin line, its
comment, and the docstring growth sentence its header asks for.

## Risks

- OCR quality on low-resolution scans: 200 dpi is tesseract's sweet spot for print; the page cap,
  the per-page timeout and the 10-minute document deadline bound the cost of a bad file.
- A born-digital PDF with a little text and a logo image fires the trigger. Its OCR text then
  replaces the sparse text layer; the recognised text includes what the layer held, but only for
  pages within the cap (pages past the cap lose their sparse text layer).
