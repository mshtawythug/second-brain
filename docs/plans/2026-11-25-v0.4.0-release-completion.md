# Plan: finish and release secondbrain-py 0.4.0

> **For agentic workers:** REQUIRED SUB-SKILL: Use team-driven-development to implement this plan task-by-task.

**Spec:** `docs/specs/2026-11-25-v0.4.0-release-completion-design.md`. The spec holds the checklist of
what is done; this plan is the order of the remaining work and who does it.

**Roles:**
- **team-lead** coordinates and asks the owner.
- **ops-merge** merges, runs the post-merge steps and handles disk and prod operations.
- **qa-lead** runs the re-test.
- **fix-lead** handles any fix round the re-test needs.

## Step 1: finish the merge queue (ops-merge)

Merge order: #140 (done, `c845abdf`) → #142 → #141 → #137 → #139.

For each PR:
1. `gh pr view N --json mergeable,headRefOid`. The head must equal the approved SHA and the PR must be MERGEABLE.
2. `gh pr merge N --merge --match-head-commit <approved sha>`.
3. Post-merge:
   - fast-forward the main checkout;
   - `scripts/check_ceiling_table.py`;
   - reinstall the daemon from `.claude/worktrees/daemon-src`, then diff its RECORD;
   - `nc -z 127.0.0.1 55432`, then kickstart `com.brain.watcher`;
   - `bin/brain-skills-sync` if `skills/` changed (it did for #140);
   - remove the worktree (no `--force`) and the branch (`git branch -d`);
   - drop the PR's test DBs by exact name.
4. If the next PR turns CONFLICTING, stop the queue. fix-lead merges master into that branch (never a
   rebase), CI reruns, and review and audit re-issue their verdicts at the new SHA. Then the queue resumes.

## Step 2: re-test on the final master (qa-lead)

1. `df` ≥ 6.5 GiB. Export the source with `git archive <final sha>`, build the wheel, and install it into
   a fresh `venv-<sha>` in `~/workspace/brain-qa/`.
2. Re-run the guard proofs (P0–P9) and the preflight against the new venv.
3. Check `src/brain/migrations` for new files. If there are any, run `qbrain init` on `brain_qa_a`–`d`.
4. Re-run the rows for every fixed finding:
   - F1–F4, F7, F10, F12, F13, F15–F25, F27–F29, F34, F37, F41;
   - F41 and F21 are checked statically (code reading plus unit tests). Nothing connects to `:55432`;
   - C24 restore runs on the age-test lane DB only. Drop each `brain_qa_c_replaced_<ts>` DB it creates by exact name.
5. Report each finding as FIXED or NOT FIXED, with a row verdict. Append a "Re-test" section to
   `REPORT.md`, which stays local and is never published.

**Done when:** every listed finding is FIXED, or each NOT FIXED one has an owner decision (fix before the
tag, or backlog).

## Step 3: fix round, only if Step 2 finds a regression (fix-lead)

Same workflow as the other fixes: plan, then TDD, then a PR with green CI, review and audit, then the
ops-merge merge. After that, Step 2 re-runs for the affected rows only.

## Step 4: release (team-lead and ops-merge)

1. Confirm master CI is 5/5 green for the release SHA.
2. Check the CHANGELOG `## 0.4.0` section against the merged PRs, and ask the owner whether to move the
   date to the release day.
3. **Ask the owner "go tag"** and wait for the explicit yes.
4. `git tag -a v0.4.0 <sha> -m "v0.4.0" && git push second-brain v0.4.0`.
5. Watch `release.yml`, then confirm `secondbrain-py 0.4.0` is on PyPI.
6. Follow-up PR, with review: bracket the `0.4.0` heading, add the `[0.4.0]:` compare link, retarget
   `[Unreleased]` to `v0.4.0...HEAD`. (This spec and plan were committed earlier, by PR #143.)

## Step 5: wrap-up

1. Update the memory files (`cli.md`, `schema.md`, `types.md`, MEMORY.md) to the merged state.
2. Drop the QA lane DBs (`brain_qa`, `brain_qa_a`–`d`) by exact name, and delete the QA venvs.
3. Shut down the teammates.
4. Hand the owner the post-release list: backlog BL-57..98, Dependabot #134 and #71, and the staged macOS
   update, which would free about 15 GiB.

## Risks

- **Low disk** (about 9 GiB free): the re-test needs ≥6.5 GiB. The DISK HOLD watchdog alerts at 6 GiB.
- **Session idling:** team-lead watches the queue directly with a background watcher instead of waiting
  on agent reports.
- **Prod safety:** no step connects to `:55432` except the post-merge `nc -z` probe and the watcher kickstart.
