## Goal

`brain mcp serve` runs an opt-in streamable-HTTP MCP endpoint, so a second device on a private
network (a tailnet) can call the brain's read tools. The defaults are:

- **Off.** Nothing listens until the command runs (RM-46.D1).
- **Loopback.** Binding any other address needs both `--allow-remote` and a bearer token.
- **Authenticated.** A 256-bit bearer token lives in a 0600 file.
- **Read-only.** Every tool not on an explicit read list is removed from the registry.
- **Confidential-excluded.** A call that asks for confidential documents is refused unless
  `--include-confidential` was given (D4).

`brain-mcp` (stdio) behaves as it does today. The one change is that it now refuses arguments
(D10).

## Hard constraints (restated in every teammate brief)

- Never touch `~/brain-vault` or `data/postgres`, and never connect to 55432. The test DB is
  `second_brain_test_rm46` on 5434. Every shell exports
  `BRAIN_PROD_DATABASE_URL=postgresql://localhost:1/none BRAIN_SKIP_CANARY=1`.
- Every test, and the e2e, sets `BRAIN_HOME` to a `tmp_path` or scratch directory, so a token file
  is never written to or read from the owner's real `~/.brain`. A test that resolves the default
  token path asserts that the path is under `tmp_path`.
- Network use is loopback only: the e2e binds `127.0.0.1` on an ephemeral port. No test binds
  `0.0.0.0` or a LAN address. The non-loopback cases are tested through `validate_options` and an
  injected resolver, without opening a socket.
- No PII. Hostnames are `*.example.com` (`brain.tailnet.example.com`), addresses come from the
  documentation ranges (`192.0.2.x`, `2001:db8::/32`), and the docs use paths like `/Users/you`.
- No logging of tokens, headers, bodies, query strings or raw paths. Exception classes end in
  `Error` and are never stored on an attribute. No logger call carries an exception message (G1).
- No `--no-verify`, no amend, no rebase, no force-push. Kill processes by PID only, and leave no
  background process behind. Never publish to claude.ai.

## The request pipeline (outside in)

```
uvicorn (pre-bound sockets, proxy_headers=False, server_header=False,
         limit_concurrency=16, timeout_keep_alive=5, timeout_graceful_shutdown=10, access_log=False)
└─ RequestLogMiddleware        one line per request; sees scope + response status only
   └─ HostGuardMiddleware      421 for a Host outside the allowlist, on EVERY path
      └─ HealthRoutes          GET /healthz → {"status":"ok"} (no auth); /readyz falls through
         └─ BearerAuthMiddleware   401 (identical body for every failure); exempt: /healthz only
            └─ HealthRoutes(readyz)  GET /readyz → readiness (auth required when auth is on)
               └─ ConfidentialGateMiddleware   (absent with --include-confidential)
                  └─ SDK streamable_http_app(stateless, json_response, explicit TransportSecuritySettings,
                                             max_request_body_size)
```

Lifespan scopes pass straight through every layer, because the SDK app's lifespan runs its session
manager. Every layer is pure ASGI (the `brain.ui.security` precedent), and none of them catches
exceptions.

- **Auth before any body read.** An unauthenticated request never reaches a layer that buffers. The
  token is compared as **bytes** with `hmac.compare_digest`. `brain ui`'s review round 5 found
  that `compare_digest` raises `TypeError` on non-ASCII `str`. A header that is not ASCII, has the
  wrong scheme, or has the wrong length still gets the same 401. Only the first `authorization`
  header is read. If a request carries two, it is refused.
- **Route labels, not paths, in logs.** The log records `endpoint`, `healthz`, `readyz` or `other`,
  never `scope["path"]`. The path is attacker-controlled and unbounded. The client address comes
  from the socket (`proxy_headers=False`), so `X-Forwarded-For` cannot forge it.
- **`/readyz`** runs `SELECT 1` on a fresh connection in `anyio.to_thread.run_sync`, under the
  config's `connect_timeout` plus a 2 s `statement_timeout`. That way the event loop never blocks
  and a dead database answers `"database": "unavailable"` with HTTP 200 instead of hanging. The
  body is R1's, with `tools` as the real advertised count. It carries no corpus statistics.

## Security threat model (untrusted input: everything on the socket)

| # | Threat | Guard | Test |
|---|---|---|---|
| T1 | Accidental network exposure | Loopback default. A non-loopback address (judged on the resolved address, after one resolution) needs `--allow-remote` **and** a token. `--no-auth` is loopback only. The sockets are bound before uvicorn starts and handed to it, so nothing re-resolves the host (`brain ui` rounds 10–16). The refusal text names a tailnet and forbids port-forwarding. | bind-guard tests with an injected resolver: `0.0.0.0`, `::`, a LAN literal, `localhost`→`192.0.2.1`, `alias.example.com`→`127.0.0.1` (a loopback alias must need a token), `127.0.0.2` (loopback by address) |
| T2 | Token theft from disk | Created at 0600 via `O_EXCL\|O_NOFOLLOW`, rotated through a temp sibling and `os.replace`. Read with `O_NOFOLLOW` plus `fstat`: it must be a regular file, owned by this uid, with no group/other bits. Otherwise the server refuses to bind, before opening a socket. | symlink planted at the path; FIFO; another owner's file (a fake `stat` result through an injected `stat_fn`); 0644; 0400 accepted |
| T3 | Token leak through logs, the banner or reprs | `secret` has `repr=False`. Logs carry fixed reason strings. The banner shows only the fingerprint. The settings error never echoes the value. uvicorn's access log is off. | `caplog` over 401 and 200 responses: the secret appears in no record; `repr(TokenInfo)` and `repr(McpHttpSettings)` do not contain it |
| T4 | Token guessing or timing | 256-bit `secrets.token_urlsafe(32)`, a byte-wise `compare_digest`, and one byte-identical 401 response for every failure. | missing, wrong scheme, wrong token, non-ASCII header and two headers each give the same 401 bytes |
| T5 | Oversized or bomb token file | `read_token` reads at most 4 KiB+1. More is refused, and so is anything outside the token charset after a single strip of one trailing newline. | 1 MiB file; NUL bytes; CRLF; multibyte characters |

| T10 | Concurrent tool calls sharing one psycopg connection | HTTP state uses per-call connections (D5). | a two-thread concurrency test against 5434: two overlapping `brain_search` calls through the ASGI app both succeed |
| T11 | Log injection or forged client address | Route labels only. The client address comes from the socket (`proxy_headers=False`). | `X-Forwarded-For: 203.0.113.9` is not logged; a path with `%0d%0a` logs as `other` |
| T12 | Corpus statistics leaked through health endpoints | `/healthz` returns a static body. `/readyz` is token-gated and carries no counts, paths, names or version beyond R1's fields. | exact-body tests |

1. **`brain_gaps` is a write tool.** A scan of every read tool's parameters found

   the second layer, as planned.

   `--call-timeout` (default 300 s, range 1–3600, 504) and an 8 MiB result cap (502), in
   `ResponseGuardMiddleware`. The deadline stops the wait, not a sync tool already on a
   worker thread. *(Corrected in the sec-118/rev-118 round: the first version said "the
   concurrency cap bounds how many such threads there can be", which was false, because
   uvicorn's cap freed the slot at the 504 while the thread ran on. What bounds them now:
   the worker-thread CapacityLimiter, capped at 16 by `WorkLimitMiddleware`, whose token
   an orphan holds until it returns, plus a `statement_timeout` on every per-call
   connection.)*
4. **`start_state` replaces `install_state`** (D8). It builds, installs and warms up, so
   `brain mcp serve` does not reach for the private `_warmup_embed`. HTTP passes

   `BRAIN_MCP_TOKEN_PATH`, then `<brain_home>/mcp_token`. The env token is R1's override, so
   it outranks a file found by default.
6. **A loopback bind with no token needs `--no-auth` explicitly.** It fails closed with
   "no bearer token" instead of serving unauthenticated by default.
7. **`--allowed-host`** takes a bare hostname or IP. A port, scheme, path, wildcard or `0.0.0.0`
   is refused, and the `:*` form is added for the SDK's check.
8. **Tests are laid out differently from the plan's table.** `test_mcp_http_app.py` (in
